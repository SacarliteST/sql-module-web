# SQL Module Web — дорожная карта

Актуализировано: 2026-09-12.

Документ фиксирует крупные этапы развития frontend SQL-модуля. Оперативные
статусы ведутся в `docs/TECH_DEBT.md`, `docs/STUDENT_CONTOUR_KANBAN.md`,
`docs/PLATFORM_INTEGRATION_KANBAN.md` и
`docs/TEACHER_AUTHORING_INTEGRATION_KANBAN.md`.

Концепция новой модели проверки заданий второй итерации описана в
`docs/SECOND_ITERATION_TASK_VALIDATION_CONCEPT.md`.

## 1. Текущее состояние

Первая продуктовая итерация завершила основной MVP. Реализованы:

- автономный режим с входом через IdentityService;
- роли `Admin`, `Teacher` и `Student` с раздельными маршрутами;
- преподавательский цикл: темы, учебные базы, схема, исходные данные, задания и
  эталонный SQL-запрос;
- визуальный конструктор схемы, проверка изменений и read-only ER-диаграмма;
- студенческий каталог, карточка задания, Monaco, локальный черновик, отправка
  попытки, вердикт, фактический результат и история;
- идемпотентная отправка попыток;
- платформенный запуск студента через `/launch` с модульной сессией;
- платформенный запуск преподавателя через `/teacher/launch` без повторного входа;
- возврат студента на платформу после правильного решения;
- общий `TokenProvider`, разделяющий standalone- и handoff-сессии.

Standalone остаётся обязательным режимом. Платформенная интеграция дополняет его,
а не заменяет.

## 2. Зафиксированные решения

| Область | Решение |
|---|---|
| Приложение | React SPA с `mount(element, config)` и runtime-конфигурацией |
| UI | React 19, TypeScript, Vite и Mantine |
| Состояние сервера | TanStack Query |
| Сессия | Zustand и заменяемый `TokenProvider` |
| Формы | React Hook Form и Zod |
| API | Orval по Swagger; generated-файлы вручную не меняются |
| SQL | Monaco Editor |
| Схема | React Flow и ELK |
| Student handoff | JWT во fragment, `session_id`, `sessions/current` |
| Teacher handoff | JWT во fragment, без `ModuleSession` и `session_id` |
| Оценивание | Первая правильная попытка завершает сессию оценкой 100 |

## 4. Итерация 2 — стабилизация и развитие

### 4.1. Production-интеграция

1. Завершить `SQLI-019`: CSP, `Referrer-Policy`, redaction и наблюдаемость.
2. Завершить `SQLI-022`: standalone smoke после интеграционных изменений.
3. Выполнить `SQLI-023`: Platform → launch → attempt → Kafka → grade → return.
4. Выполнить `TAI-011`: authoring handoff с созданием полного комплекта контента.
5. Выполнить `TAI-012`: TLS, SPA fallback, base path и заголовки на VPS.

### 4.2. Масштабирование списков

1. `STU-019`: серверный поиск и пагинация заданий в истории.
2. `TD-005`: серверный поиск и пагинация тем, заданий и учебных баз.
3. Deep links и восстановление выбранных значений после reload.

### 4.3. Производительность

1. `TD-002`: ленивые Teacher/Admin routes и аудит barrel imports.
2. `STU-027`: бюджеты initial, Monaco и ER chunks.
3. Проверка холодной загрузки каталогов, Monaco и ER-диаграммы.

Текущие ориентиры: основной chunk около 775 KB, ER chunk около 1,63 MB, Monaco
chunk около 2,66 MB. Лимит предупреждения Vite искусственно не повышается.

### 4.4. Интерактивная ER-диаграмма

- выбор таблицы и колонки на графе синхронизируется с формой;
- изменения формы отражаются на диаграмме;
- внешние связи создаются и удаляются графически;
- backend violations подсвечивают проблемный элемент;
- ручное расположение узлов не теряется при автоматической раскладке;
- табличная форма остаётся доступным источником данных.

### 4.5. Schema-aware Monaco

- completion таблиц, колонок и алиасов;
- подсказки после `alias.`;
- функции и ключевые слова выбранного SQL-диалекта;
- общий provider для эталонного и студенческого редакторов;
- отсутствие эталонных данных в student-контуре.

### 4.6. Устойчивость Student UX

Порядок: `STU-023 → STU-024 → STU-025 → STU-026 → STU-028 → STU-029 →
STU-030`.

Сюда входят длинные значения result grid, диапазон дат, field errors, undo-safe
форматирование, lifecycle черновиков, URL-состояние и единый trace ID.

### 4.7. Регрессионная защита

После стабилизации контрактов выполнить `STU-020`:

- unit/component-тесты идемпотентности, token providers, черновиков, enum mapping,
  snapshot и URL-фильтров;
- автоматизированный smoke Teacher/Student на тестовом окружении;
- typecheck, production build и bundle budgets в CI.

## 5. Отдельные продуктовые решения

`STU-021` остаётся заблокированной до выбора модели отмены: оставить синхронный
submit без обещания серверной отмены либо внедрить состояния
`Queued/Running/Completed/Cancelled` и cancel API. Для второй итерации
предпочтительна синхронная модель.

Назначения заданий группам, дедлайны, число попыток, аналитика преподавателя,
импорт/экспорт и шифрование `sessionKey` требуют отдельных ТЗ и не считаются
автоматически включёнными в итерацию 2.
