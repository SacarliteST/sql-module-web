# sql-module-web — Цели разработки (ROADMAP)

Высокоуровневый трекер фаз фронтенда модуля **SQLModule**. Детальные требования и критерии —
в `ТЗ.md`; архитектура и стек — в `CONCEPT.md`. Принцип: **сначала концепт → промт для агента →
реализация → проверка**.

> **Статус.** Старт проекта. Делаем **standalone** SPA, встраивание — позже. Бэкенд (SQLModule Фаза 1
> и IdentityService v1) готов — задача фронта — собрать UI поверх существующих эндпоинтов.
> Значки: ✅ сделано / 🔶 в работе / 🔲 запланировано.

## 3. Область v1

Делаем:
- UI двух контуров (Teacher, Student) поверх готовых эндпоинтов.
- Standalone-режим с входом через IdentityService; архитектурный задел под embedding.
- Полный цикл «СУБД → схема → данные → задание → решение → вердикт».

НЕ делаем в v1:
- Управление пользователями/ролями и регистрацию сотрудников (зона хоста/Identity).
- Полноценную embedded-интеграцию в конкретный хост (только задел и проверка монтирования).
- Цифровой след в реальном времени (события/SignalR), нечёткое сравнение в UI — ждут Фазы 2 бэкенда.
- Полноценный OAuth2/OIDC redirect-флоу.

---

## 4. Зависимости от бэкенда

- Актуальные OpenAPI-документы обоих сервисов (для orval) и включённый CORS для адреса фронта.
- Согласованные имена claim (`sub`/`role`/`name`/`email`) и ролей (Student/Teacher/Admin).
- Учитывать открытый бэкенд-долг: иммутабельность финализированной схемы (UI должен блокировать правку).
