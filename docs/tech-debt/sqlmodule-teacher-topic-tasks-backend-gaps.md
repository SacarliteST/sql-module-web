# SQL Module: доработки API для блока заданий темы

## Контекст

На странице преподавателя `Темы` реализован блок `Задания темы`.
Сейчас фронт получает данные через существующие клиенты:

- `GET /api/v1/sql-tasks`;
- `GET /api/v1/sql-queries`;
- `GET /api/v1/target-dbs`;
- `GET /api/v1/dbms-dictionaries`.

Фильтрация заданий по выбранной теме пока выполняется на фронте по `topicId`.
Название базы и СУБД собираются через связь:

```text
SqlTask.sqlQueryId -> SqlQuery.targetDbId -> TargetDb.dbmsId -> DbmsDictionary
```

## Что желательно доработать на бэке

1. Добавить фильтр `TopicId` в список SQL-заданий:

```http
GET /api/v1/sql-tasks?TopicId={topicId}&Offset=0&Limit=20
```

Сейчас `GetAllSqlTasksParams` содержит только `Offset` и `Limit`, поэтому фронт вынужден загружать до 100 заданий и фильтровать их локально.

2. Добавить агрегированный read model для списка заданий преподавателя.

Желаемый ответ для строки таблицы:

```json
{
  "id": "uuid",
  "topicId": "uuid",
  "taskName": "Базовый SELECT из таблицы сотрудников",
  "difficultyLevel": 1,
  "targetDbId": "uuid",
  "targetDbName": "UniversityDB",
  "dbmsId": "uuid",
  "dbmsName": "PostgreSQL",
  "attemptsCount": 28,
  "publicationStatus": "Published",
  "updatedAt": "2026-07-18T10:00:00Z"
}
```

3. Добавить счётчик попыток по заданию.

На текущем фронте поле выводится как `н/д`, потому что `SqlTaskResponse` не содержит `attemptsCount`.

4. Добавить статус публикации задания, если он есть в доменной модели.

В макете есть визуальный статус `Опубликовано`, но текущий `SqlTaskResponse` не содержит статуса. Пока вместо него показывается `difficultyLevel`, потому что колонка называется `Сложность`.

5. Добавить фильтры для эталонных SQL-запросов, если агрегированный read model пока не планируется:

```http
GET /api/v1/sql-queries?TargetDbId={targetDbId}
GET /api/v1/sql-queries?Ids={id1}&Ids={id2}
```

Иначе фронт будет вынужден грузить полный список эталонных запросов для связки задания с базой.

## Приоритет

Высокий для пункта 1: без серверной фильтрации список заданий темы некорректно масштабируется.

Средний для пункта 2: агрегированный read model упростит фронт и уменьшит количество запросов.

Средний для пунктов 3-4: нужны для полного соответствия макету.
