# Пункт 3. Смена темы и эталонного SQL-запроса

Дата реализации: 2026-07-26.

Статус: `Готово`.

## Контракт

`UpdateSqlTaskRequest` расширен опциональными полями:

```json
{
  "taskName": "Выбор сотрудников",
  "taskText": "Выведите сотрудников.",
  "difficultyLevel": 1,
  "publicationStatus": "Draft",
  "topicId": "guid",
  "sqlQueryId": "guid"
}
```

Если `topicId` или `sqlQueryId` равен `null` или отсутствует, соответствующая
текущая связь сохраняется.

## Бизнес-правила

Фактически изменить тему или эталонный запрос можно только когда:

- задание находится в статусе `Draft`;
- у задания нет ни одной попытки;
- новая тема существует;
- новый эталонный SQL-запрос существует.

Для `Published` и `Archived` изменение связей возвращает `409 Conflict`.

Задание `Draft` с попытками также получает `409 Conflict`.

Проверка применяется только при фактической смене идентификатора. Повторная
передача текущих `topicId` и `sqlQueryId` не считается изменением связей.
Это сохраняет совместимость формы с редактированием контента опубликованного задания.

## Доменная модель

В `SqlTask` добавлена отдельная операция:

```csharp
UpdateLinks(Guid topicId, Guid sqlQueryId)
```

Проверки состояния и существования связанных сущностей выполняются в
`UpdateSqlTaskHandler` до изменения агрегата.

## Ошибки

Добавлены отдельные бизнес-ошибки:

- связи можно менять только у `Draft`;
- связи нельзя менять после появления попыток;
- новая тема не найдена;
- новый эталонный запрос не найден.

Единый формат ProblemDetails будет реализован в следующем пункте плана.

Generated-модель `UpdateSqlTaskRequest` теперь содержит опциональные:


Generated-файлы вручную не редактировались.

## Внедрение во фронт

Фронт применяет новую политику смены связей в модальном окне задания.

Правила UI:

1. Для нового задания тема и эталонный SQL-запрос выбираются как раньше.
2. Для существующего задания поля `Тема` и `Эталонный SQL-запрос` доступны для изменения только если:
   - задание в статусе `Draft`;
   - у задания нет попыток.
3. Для `Published`, `Archived` и заданий с попытками связи отображаются как read-only контекст.
4. При edit-submit фронт отправляет `topicId` и `sqlQueryId` в `PUT /api/v1/sql-tasks/{id}`.
5. Если связь не выбрана, фронт отправляет `null`, чтобы backend сохранил текущую связь.
6. В форме сохранена совместимость с опубликованным заданием: повторная передача текущих связей не считается попыткой смены.
7. На странице деталей задания теперь загружаются справочники тем, SQL-запросов, учебных баз и СУБД, чтобы edit-модалка могла дать полный выбор для разрешённого случая.

Проверка preview эталонного SQL из пункта 2 автоматически работает и для нового выбранного
`sqlQueryId`, потому что preview-компонент получает актуальные `queryText` и `targetDbId`.
