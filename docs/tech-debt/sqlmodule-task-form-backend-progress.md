## Пункт 1. Безопасная публикация задания

Дата реализации: 2026-07-26.

### API

Добавлена операция:

```http
POST /api/v1/sql-tasks/{id}/publish
```

Успешный ответ — `200 OK` с актуальным `SqlTaskResponse`.

Операция доступна для политики `ContentAuthor`, как и создание/изменение учебного контента.

### Принятые правила

1. Новое задание создаётся только в статусе `Draft`.
2. Обычный `PUT /api/v1/sql-tasks/{id}` не переводит `Draft` или `Archived` в `Published`.
3. Для совместимости обычное редактирование уже опубликованного задания допускает повторную передачу текущего значения `Published`.
4. Повторная публикация уже опубликованного задания возвращает `409 Conflict`.
5. Архивное задание нельзя опубликовать.
6. Задание с существующими попытками нельзя опубликовать.
7. Эталонный SQL-запрос должен иметь сохранённый golden result (`ExpectedResult`).
8. Связанная учебная база данных должна существовать.

Отдельный признак активности у `TargetDb` в текущей доменной модели отсутствует, поэтому проверка `isActive/available` пока ограничена существованием связанной записи.

### Ошибки

Добавлены отдельные бизнес-ошибки для:

- создания задания не в `Draft`;
- попытки публикации через обычный update;
- повторной публикации;
- публикации архивного задания;
- публикации задания с попытками;
- отсутствия проверенного эталонного результата;
- отсутствия учебной базы.

Формат ProblemDetails будет унифицирован отдельно в пункте 3.
