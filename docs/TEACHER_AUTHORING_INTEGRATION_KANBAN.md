# Kanban перехода преподавателя из платформы в SQL-модуль

Актуализировано: 2026-09-10.

Доска содержит только работы, относящиеся к SQL-модулю:
`Frontend/sql-module-web` и проверки `Backend/SqlModule`. Изменения Education и
`platform-web` являются внешними зависимостями и в этой доске не реализуются.

Источник требований:
`C:/Users/vladislav.bokovoi/Downloads/20260910teacherauthoringhandoff.md`.

## Цель

Преподаватель, уже авторизованный на платформе, открывает SQL-модуль в новой
вкладке без повторного ввода логина и пароля и получает доступ к существующему
контуру авторинга: темам, учебным базам данных, SQL-заданиям и эталонным запросам.

Это не регистрация новых пользователей. Платформа передаёт короткоживущий JWT
существующего преподавателя с ролью `Teacher` или `Admin` и audience
`sql-module-api`.

## Зафиксированные решения

- публичная точка входа модуля — `/teacher/launch`;
- access token передаётся только во фрагменте `#access_token=...`;
- токен немедленно удаляется из адресной строки;
- handoff-токен хранится только в `sessionStorage`;
- refresh token и автоматическое обновление handoff-сессии отсутствуют;
- преподавательский запуск не создаёт `ModuleSession` и не требует `session_id`;
- `GET /module-integration/sessions/current` не вызывается;
- `ActiveLaunchContext` и студенческий `returnUrl` не создаются;
- авторинг разрешён политикой `ContentAuthor` для `Teacher` и `Admin`;
- standalone-вход SQL-модуля должен продолжить работать независимо от платформы.

## Детализация frontend-задач

### TAI-001 — общий launch helper

- вынести чтение `access_token` из `window.location.hash` из `LaunchPage`;
- очищать fragment через `history.replaceState` до любых сетевых запросов;
- сохранить поддержку повторного эффекта React Strict Mode;
- перевести существующий студенческий `/launch` на новый helper;
- не менять generated API-клиенты.

### TAI-002 — `TeacherLaunchPage`

- добавить `src/session/ui/TeacherLaunchPage.tsx` и публичные экспорты;
- принимать только декодируемый JWT с ролью `Teacher` или `Admin`;
- записывать access token через `createHandoffTokenProvider`;
- активировать provider через `setActiveTokenProvider`;
- вызвать `setTransientSession({ accessToken, user })`;
- выполнить `navigate('/teacher/topics', { replace: true })`;
- не вызывать API текущей студенческой модульной сессии;
- при ошибке очистить частично созданное handoff-состояние.

### TAI-003 — маршрут

- зарегистрировать публичный `/teacher/launch` рядом со студенческим `/launch`;
- не оборачивать launch-страницу в `RequireAuth`;
- проверить прямое открытие маршрута и работу с настроенным `basename`.

### TAI-004 — роли

- заменить дублирующиеся `allowedRoles={['Teacher']}` на единый author-role guard;
- разрешить `Teacher` и `Admin`, как требует `ContentAuthor` backend;
- не расширять доступ к `/admin/*` для преподавателя.

### TAI-005 — разделение контекстов

- преподавательский запуск не должен записывать `ActiveLaunchContext`;
- исключить отображение студенческого возврата в платформу в teacher-flow;
- безопасно удалить устаревший student-context при новом teacher handoff;
- убедиться, что teacher-запросы не получают и не требуют `session_id`.

### TAI-006 — жизненный цикл сессии

- зафиксировать и реализовать поведение при logout и общем ответе 401;
- очистить `HANDOFF_ACCESS_TOKEN_STORAGE_KEY` и вернуть активный provider в
  standalone-режим;
- не удалять сохранённую standalone-сессию из `localStorage`;
- устранить текущее промежуточное состояние, когда standalone-токен сохранён, но
  UI остаётся анонимным до перезагрузки.

### TAI-007 — ошибки

- отдельные состояния: отсутствующий/повреждённый токен и истёкшая сессия;
- сообщение предлагает вернуться на платформу и открыть модуль заново;
- токен, JWT claims и техническое тело ошибки не отображаются;
- данные формы при истечении токена пока не восстанавливаются — это допустимое
  ограничение MVP.

## Внешние зависимости

| Система | Требование |
|---|---|
| Education | `POST /api/v1/practical-modules/{id}/authoring-link` возвращает URL `/teacher/launch#access_token=...` и доступен преподавателю |
| IdentityService | Выпускает короткоживущий JWT с `aud=sql-module-api`, ролью `Teacher`/`Admin` и без `session_id` |
| platform-web | Открывает полученный URL через `window.open(..., '_blank', 'noopener,noreferrer')` и обрабатывает ошибки Education |
| Reverse proxy | Проксирует base path SQL-модуля и поддерживает SPA fallback для `/teacher/launch` |

## Критерии готовности

1. Преподаватель открывает SQL-модуль из платформы без повторного ввода пароля.
2. После обработки ссылки токен отсутствует в адресной строке.
3. Пользователь попадает на `/teacher/topics` и может создать тему, учебную БД,
   SQL-задание и эталонный запрос.
4. Токен Student, пустой или повреждённый токен не дают доступ к авторингу.
5. Авторские endpoints принимают Teacher JWT без `session_id`.
6. Закрытие вкладки удаляет handoff-сессию; refresh token не создаётся.
7. Logout и 401 не повреждают сохранённый standalone-профиль.
8. Обычный teacher login и студенческий `/launch` проходят регрессионный smoke.
9. Frontend typecheck и production build проходят.
